Gestion de projet

Méthode, outils, découpage et déroulement

1. Contexte et contraintes

Projet individuel réalisé dans le cadre de l'évaluation en cours de formation (ECF) du titre professionnel Développeur Web et Web Mobile, avec une date de rendu fixée au 19/11/2026. Le temps disponible était très limité (activité professionnelle à mon compte et vie de famille en parallèle).

Transparence : l'ensemble du projet (analyse, code, tests et documentation) a été réalisé avec l'assistant d'intelligence artificielle Claude (Anthropic), que j'ai piloté : je fixais les objectifs à partir de l'énoncé, l'IA proposait et écrivait, je relisais, testais et validais. Ce mode de travail est décrit dans ma copie.

2. Méthode : Kanban

J'ai choisi une méthode agile de type Kanban, adaptée à un développeur seul : pas de sprints à durée fixe, mais un flux continu de tâches visibles sur un tableau, avec une limite de travail en cours (une seule fonctionnalité en développement à la fois). Chaque carte correspond à une fonctionnalité de l'énoncé et à une branche Git.

ColonneRôle
À faire (backlog)Toutes les fonctionnalités extraites de l'énoncé, classées par priorité.
En coursUne seule carte à la fois ; une branche feature/… est créée.
TestsTests manuels du parcours, tests unitaires, vérifications de sécurité et d'accessibilité.
TerminéBranche fusionnée dans develop.

3. Organisation Git

  • main : branche principale, version stable et déployée.
  • develop : branche d'intégration.
  • feature/… : une branche par fonctionnalité, créée depuis develop, fusionnée dans develop après test (git merge --no-ff pour garder la trace de chaque fonctionnalité dans l'historique).
  • Quand develop est testée dans son ensemble, elle est fusionnée dans main.

6. Suivi de la qualité

  • Définition de « terminé » pour chaque carte : parcours testé dans le navigateur, aucune erreur PHP, contrôles de sécurité (CSRF, droits, saisies invalides) vérifiés, code commenté, branche fusionnée.
  • Tests automatisés : 25 tests PHPUnit (validation, mots de passe, CSRF, rendu des avatars).
  • Tests de parcours : script de requêtes HTTP rejouant les parcours joueur, employé et administrateur.
  • Accessibilité : navigation au clavier, lecteur d'écran sur les composants dynamiques, contrastes calculés.
